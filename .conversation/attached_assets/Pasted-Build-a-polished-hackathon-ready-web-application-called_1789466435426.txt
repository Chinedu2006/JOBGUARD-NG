Build a polished hackathon-ready web application called "JOBGUARD NG".

PRODUCT PURPOSE
JOBGUARD NG helps Nigerian young people evaluate suspicious job, internship, scholarship, grant, fellowship, and recruitment opportunities before they send money or sensitive information.

Core message:
"Before you chase the opportunity, check the opportunity."

The product should feel like a real Nigerian startup MVP, not a generic AI demo.

IMPORTANT:
This is an MVP for a hackathon. Prioritize:
1. A working end-to-end experience
2. Excellent UX
3. Explainable results
4. Nigerian context
5. Fast performance
6. Mobile responsiveness
7. A compelling live demo

Do NOT add authentication, payments, admin dashboards, complicated account systems, or unnecessary features unless they are required for the core experience.

TECHNICAL DIRECTION
Use a modern full-stack web architecture that works reliably on Replit.
Prefer:
- React
- TypeScript
- Tailwind CSS
- A simple backend/API
- SQLite or another simple Replit-compatible database if persistence is needed

Keep the code modular and easy to modify.

The application must run correctly with one Replit Run command.

Create a prominent section titled:

"Check an Opportunity"

TAB 1:

3. RISK ANALYSIS ENGINE
==================================================

Do NOT make the product simply return:

"AI says this is a scam."

Create an explainable risk scoring system from 0–100.

The analysis should look for signals such as:

- Payment or registration fees
- Requests for bank transfers
- Requests for cryptocurrency
- Requests for BVN
- Requests for NIN
- Requests for OTPs
- Requests for passwords
- Requests for unusual personal information
- Artificial urgency
- "Guaranteed job" language
- "Pay to secure your slot" language
- Suspicious contact methods
- Personal email addresses for supposedly official organizations
- Suspicious or mismatched URLs
- Poorly structured recruitment claims
- Unrealistic salary promises
- Requests to move immediately to Telegram or WhatsApp
- Missing organization information
- Lack of official application instructions

Use weighted rules to calculate a transparent score.

Example:

Payment requested: +25
Sensitive information requested: +20
Suspicious contact method: +15
Artificial urgency: +10
Unverified source: +15
Unrealistic promise: +10
Suspicious URL: +5

The weights should be configurable in one place in the code.

Do not claim that the score is scientifically accurate.

4. RESULTS SCREEN
==================================================

After analysis, show a visually strong results screen.

At the top display:

"Opportunity Risk Assessment"

Then show a large circular or horizontal risk meter.

Example:

87 / 100

HIGH RISK

Use these categories:

0–30:
LOW RISK

31–60:
PROCEED WITH CAUTION

61–80:
HIGH RISK

81–100:
VERY HIGH RISK

Do not call any opportunity "100% scam".

Instead use language such as:

"High risk based on the signals detected."

Under the score display:

"Why we flagged this"

Show individual warning cards.

Example:

RED FLAG
"Payment requested"

"Legitimate recruitment opportunities generally should not require applicants to pay to secure a position."

RED FLAG
"Urgency language"

"The message pressures the applicant to pay immediately or lose the opportunity."

WARNING
"Unverified source"

"The organization or opportunity could not be confirmed using the information provided."

Each detected signal should show:
- severity
- title
- short explanation

DO NOT SEND MONEY

This section must be highly visible.

When the judge clicks a demo:

2. Analyze it

Make this flow extremely fast.

The judge should be able to understand the product in less than 30 seconds.

14. SAFETY / TRUST
==================================================

Add a small footer disclaimer:

"JOBGUARD is an educational risk-assessment tool. A low-risk result does not guarantee that an opportunity is legitimate. Always verify important opportunities through the organization's official website or known official channels."

==================================================

The entire application must work beautifully on:

- mobile phones
- tablets
- laptops
- desktop screens

==================================================
16. EMPTY / ERROR STATES
==================================================

Handle all common states gracefully.

Examples:

No text entered:
"Paste an opportunity first."

Invalid URL:
"Please enter a valid link."

Analysis failure:
"We couldn't analyze this opportunity. Try pasting the message instead."

No opportunities:
"No opportunities found."

Screenshot OCR failure:
"We couldn't read the screenshot clearly. Please paste the text manually."

Never show raw technical errors to users.

Then:

"Checking for warning signs..."

Then show the result.
